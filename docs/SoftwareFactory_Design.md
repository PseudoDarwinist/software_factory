## 1. EXECUTIVE SUMMARY

- Purpose: Software Factory orchestrates AI-assisted, event-driven software delivery from idea capture to deployment. It integrates Slack/GitHub/MCP, a Mission Control UI, a Flask API+WebSocket gateway, an internal AI Broker, and a Redis-backed event bus with PostgreSQL persistence and optional pgVector-powered context.
- Architectural Tenets: Event-Driven Architecture (EDA), real-time collaboration, separation of concerns by layer, asynchronous workloads, and progressive enhancement (fallbacks when integrations aren’t available).
- AI Integration: Specialized agents (Define/Planner/Health/Impact) coordinate via an AI Broker that performs model selection, context enrichment (vector search), and queuing; external assistants connect via MCP.
- Business Value: Consistent, spec-driven delivery; traceable pipelines; parallel task execution; human-in-the-loop via Mission Control; auditable events and artifacts.


## 2. ARCHITECTURAL OVERVIEW

- Context: Frontend (Mission Control React UI) communicates with a unified Flask application that exposes REST endpoints and Socket.IO. Services handle AI orchestration, vector search, caching, background jobs, and integrations. Redis provides pub/sub; PostgreSQL persists domain data and event logs; optional pgVector enables semantic context.
- Boundaries & Interfaces:
  - External: Slack, GitHub (webhooks + APIs), IDE MCP clients (Claude/Cursor), Jenkins/Figma (optional).
  - Internal: REST API (Flask), WebSocket namespace (Flask‑SocketIO), Redis channels, SQLAlchemy models, background job manager.
- Deployment: Docker Compose provisions Postgres and Redis; the app runs on port 8000 behind gevent/Socket.IO. See `docker-compose.yml` and `src/app.py`.
- Scalability & Reliability: Horizontal scale via multiple app instances sharing Redis pub/sub + Postgres. Background jobs and WebSockets are stateless (session/JWT cached in Redis). The AI Broker uses worker threads and priority queues.

## 3. DETAILED COMPONENT ANALYSIS

### 3.1 External Systems

- Slack Integration
  - Webhook endpoint: `src/api/webhooks.py:slack_webhook` handles URL verification and event callbacks; `src/integrations/slack_adapter.py` translates payloads into internal events.
  - Message parsing and enrichment: `create_slack_message_event()` produces normalized `Event` payloads; bot messages excluded to prevent loops.
  - Channel→Project mapping: modeled via `MissionControlProject` plus custom logic in services; enrichment for ideas in Define/Think stages.
  - Real-time streaming: Slack events are translated into internal events, published to Redis via `src/services/event_bus.py` and broadcast to WebSocket clients by `src/services/websocket_server.py`.

- GitHub Integration
  - Webhook endpoint: `src/api/webhooks.py:github_webhook` handles PR, review, and comment events; updates `Task` status and creates `ValidationRun` when merged.
  - API usage: `src/integrations/github_adapter.py` and services like `github_pr_service.py`/`github_branch_service.py` handle PRs, branches, and workflow queries (token-based).
  - Branch/commit flow: The Build phase pushes feature branches; PR creation is automated in `src/services/claude_code_task_service.py`.

- MCP Server (Model Context Protocol)
  - Router: `src/mcp/router.py` exposes context and drafting endpoints; `src/mcp/server.py` runs a stdio MCP server sharing the Flask app context to ensure DB/session consistency.
  - Tools: provide project/idea context and save specification artifacts generated by external assistants.

- IDE Integrations (Kiro, Cursor, Claude Code)
  - Patterns: MCP tools and `src/services/claude_code_service.py`/`claude_code_task_service.py` bootstrap context, run agents, and sync PRs.


### 3.2 Presentation Layer (Mission Control)

- Mission Control UI
  - Stack: React + React Query + Vite (see `mission-control/src/App.tsx` and `main.tsx`).
  - Stage-based workflow: Think → Define → Plan → Build → Validate (see `src/api/stages.py` and UI pages under `mission-control/src/pages`).
  - Real-time updates: Socket.IO client in `mission-control/src/contexts/WebSocketProvider.tsx` and `mission-control/src/services/validation/validationWebSocket.ts` (auto-reconnect, batching/throttling).

- WebSocket Client Architecture
  - Connection/auth: JWT passed via `auth` in the Socket.IO handshake; reconnection with exponential backoff.
  - Topics: listens for generic `event` payloads and specific channels (e.g., `phase.transition`, validation streams).
  - Error handling: per‑topic subscriber isolation and throttled dispatch prevent UI lockups.

- UX Flows
  - Idea capture: new ideas/cards appear under Think via WebSocket as events are published.
  - Define/Spec: async spec generation progress pushed live; artifacts visible and “freeze” supported.
  - Plan/Tasks: Kanban view of parsed tasks; drag/drop to start execution; live status.
  - Build: PR links/status update via GitHub webhooks and WebSocket push.


### 3.3 API Gateway Layer (Flask)

- Application Architecture
  - Entry: `src/app.py` creates the Flask app, wires CORS, SQLAlchemy, Redis cache, Event Bus, WebSocket server, AI broker, vector services, and registers blueprints.
  - Blueprints: `src/api/*.py` cover system/health, stages, tasks, AI broker, monitoring, vector, webhooks, GitHub, conversations, etc.
  - Middleware: CORS configured for dev ports and same‑origin; minimal request logging toggled.

- WebSocket Server
  - Implementation: `src/services/websocket_server.py` via Flask‑SocketIO (gevent) with per‑user presence, room subscriptions, permission filtering, heartbeats, and broadcast helpers.
  - Security: JWT decoded by `src/services/auth_service.py`; project‑scoped authorization enforced per event and room.

- MCP Server
  - Coexists with Flask context to share DB and services; assists external AI tools with context and artifact commits (`src/mcp/server.py`).

- Endpoint Patterns
  - REST conventions with JSON responses and error handling (404/500 global handlers in `src/app.py`).
  - Notable endpoints: system status (`src/api/system.py`), stages and spec artifacts (`src/api/stages.py`), task lifecycle (`src/api/tasks.py`), webhooks (`src/api/webhooks.py`).


### 3.4 Service Layer

- AI Broker Service
  - Files: `src/services/ai_broker.py`, `src/services/ai_service.py`.
  - Model selection: task‑type and capability weighted scoring; respects load, context window, cost, and perf history.
  - Request queuing: priority queue with worker threads; sync/async submission; callbacks supported.
  - Context enrichment: vector context and role/task guidelines added unless doc‑analysis (safeguards against hallucination).

- Event Bus
  - Files: `src/services/event_bus.py` + `src/core/events.py`.
  - Redis pub/sub with thread pool dispatch; JSON envelope validation; cache invalidation hooks.
  - Complementary advanced router exists for domain events (`src/events/event_router.py`) which persists to Postgres via `src/models/event_log.py` for audit/replay.

- Spec Generation Service
  - Files: `src/services/spec_generation_service.py` + `src/services/background.py`.
  - Asynchronous orchestration: creates `IdeaPromotedEvent`, runs DefineAgent through AI Broker, broadcasts progress via WebSocket, stores `SpecificationArtifact` records, emits completion.

- Coding Assistants (BYOA)
  - `claude_code_task_service.py` provisions a git workspace, executes a Claude sub‑agent, commits changes, and auto‑opens PRs; robust progress updates surface in the UI.

- Vector Service
  - Files: `src/services/vector_service.py`.
  - Embeddings via Sentence‑Transformers (all‑MiniLM‑L6‑v2), tokenization via tiktoken, chunking with overlap. Searches via pgVector SQL UDFs with a textual fallback (ILIKE) when pgVector functions are missing.

- Authentication Service
  - Files: `src/services/auth_service.py`.
  - JWT generation/decoding, role and project‑scope validation; L1 in‑proc cache + Redis cache; guest/admin token helpers.


### 3.5 AI Agents Layer

- Define Agent
  - Files: `src/agents/define_agent.py`, bridge `src/services/define_agent_bridge.py`.
  - Repository‑aware prompts; generates requirements.md, design.md, tasks.md; stores artifacts with AI/Human/Frozen status.

- Planner Agent
  - Files: `src/services/planner_agent_bridge.py`.
  - Subscribes to `spec.frozen` and parses `tasks.md` into `Task` rows (auto‑creation is feature‑flagged/paused).

- Code Impact Analyzer & Project Health Monitor
  - Files: `src/services/ai_agents.py`.
  - Analyze system maps, conversations, and code-change signals to emit alerts with recommendations.


### 3.6 Domain Logic Layer

- Domain Packs & Business Rules
  - Represented by mission control constructs (stages, briefs, artifacts, tasks). Rules enforced in endpoints and services (e.g., PRD required before Define).

- Validation Rules
  - PRD presence checked in `src/api/stages.py:_validate_prd_requirement`; GitHub review status impacts task transitions in `src/api/webhooks.py`.

- SLA/Timing
  - Background jobs and WebSocket heartbeats enforce progress and connection freshness; Redis‑backed counters/timeouts in cache services.


### 3.7 Data Layer

- PostgreSQL
  - Models: `src/models/*` (e.g., `Task`, `SpecificationArtifact`, `BackgroundJob`, `EventLog`, `MissionControlProject`). DB init/migrations under `src/core/database.py` and Flask‑Migrate.
  - Indexing & constraints: unique spec artifacts per type and `idx_project_spec` for fast UI queries.

- Redis
  - Uses separate DBs for cache and event bus; L1/L2 cache with invalidation rules (`src/services/distributed_cache.py`).

- pgVector
  - Optional vector ops with graceful fallback to text search; context builder ensures token budget adherence.

- Event Store
  - Append‑only event tables in Postgres via `EventLog`; SQLite‑based store used by the advanced router for replay experiments.

- File Storage
  - Uploaded PRD assets via `src/api/upload.py` and models `UploadSession`, `UploadedFile`; stored under `uploads/`.


## 4. BUSINESS LOGIC FLOWS

### 4.1 Idea Capture & Processing

1) Slack Message Ingestion → `webhooks.py:slack_webhook` + `slack_adapter.py`
   - Validates URL challenge; translates message events; ignores bot messages; publishes to Event Bus.
2) Idea Enrichment
   - Tagging/mapping into `MissionControlProject`; optional PRD linkage.
3) Real-time UI Updates
   - Event Bus → WebSocket Server → UI card appears in Think stage.
4) Lifecycle
   - Status transitions tracked; assignment and analytics via models.

### 4.2 Define Phase — Specification Generation

1) Promotion Trigger
   - UI calls `POST /api/idea/{id}/move-stage` to `define`; PRD presence validated.
2) Context Gathering
   - Vector service finds relevant code/docs; PRD retrieval; embeddings prepared (guardrails skip doc‑analysis augmentation).
3) AI Generation
   - DefineAgent prompts executed by AI Broker with pass‑through for sensitive prompts; produces requirements/design/tasks.
4) Quality Assurance
   - Artifact statuses track AI Draft → Human Reviewed → Frozen; badge info computed in `SpecificationArtifact.get_badge_info()`.
5) Freezing
   - Freeze endpoints update versions; `spec.frozen` events can trigger Planner agent.

### 4.3 Plan Phase — Task Planning & Execution

1) Parse & Create
   - Planner parses `tasks.md` to `Task` rows (feature‑flagged in bridge).
2) Kanban Integration
   - Tasks surfaced in Plan board via REST; real‑time progress with WS.
3) Lifecycle
   - `READY → RUNNING → REVIEW → DONE/FAILED`, with dependency checks and progress messages.
4) Collaboration
   - Comments via PR and WebSocket updates; audit in `EventLog`.

### 4.4 Build Phase — Code Implementation

1) Execution Trigger
   - UI “Start” calls `/api/tasks/:id/start` or `start-execution`; CLAUDE SDK selected agent.
2) AI Code Generation
   - Git workspace setup; agent executes; commits pushed; PR opened.
3) QA
   - Tests can be executed in CI; PR reviews via GitHub; webhook transitions to REVIEW/DONE.
4) GitHub
   - Webhooks update status; API merges on approval if configured.
5) Deployment
   - Jenkins optional; validation runs stored.

### 4.5 Validation & Learning

- Validation
  - `ValidationRun` created on PR merge; WS pushes “phase.transition” events to the UI Validate tab.
- User Phase (Sim)
  - Synthetic checks/evidence flows via WebSocket topics.
- Learning
  - Metrics and alerts via `metrics_service`; vector store can be enriched for future context.
- Improvement
  - Feedback loops inform Define/Plan heuristics.


## 5. EVENT‑DRIVEN ARCHITECTURE

- Event Types (selected)
  - Core: see `src/core/events.py:EventType` (e.g., `spec.frozen`, `task.completed`, `build.started`).
  - Domain: see `src/events/domain_events.py` (e.g., `project.created`, `idea.captured`, `slack.message.received`, `ai.request.*`).

- Event Payloads
  - Normalized envelopes include `event_type`, `event_id`, `timestamp`, `source`, `data`, optional correlation/user/project ids.

- Processing
  - Synchronous: API endpoints may publish immediate events and respond.
  - Asynchronous: Redis pub/sub dispatch by thread pool; background jobs for long‑running tasks.
  - Chaining: Define → (spec.frozen) → Planner; Build → GitHub webhook → Validate transition queue (`src/api/system.py` pending events).
  - Persistence: Postgres `EventLog` audit trail; SQLite store for subsystem experimentation.


## 6. SECURITY ARCHITECTURE

- Authentication & Authorization
  - JWT issuance/validation in `src/services/auth_service.py`; roles + project scopes; in‑proc and Redis caches; revocation supported by cache eviction.
  - WebSocket: handshake `auth.token` decoded server‑side; event filtering by project/user and admin overrides (`websocket_server.py`).

- Data Protection
  - SQLAlchemy parameterization; Postgres over SSL recommended in production; secrets via env.
  - Input validation in adapters/endpoints; Slack signature support available in webhook service.

- Network & Compliance
  - TLS termination recommended at ingress; Prometheus port guarded; audit trail via `EventLog`.


## 7. PERFORMANCE & SCALABILITY

- Targets (defaults/guidance)
  - WebSocket round‑trip < 150ms LAN; AI responses < 45s typical; DB queries < 50ms for hot paths; API < 200ms for cached reads.
- Throughput
  - Horizontal scale with shared Redis/DB; ThreadPoolExecutors for AI and jobs; back‑pressure via queues.
- Resource Utilization
  - Vector compute at ingest; pgVector SQL for search; cache warming in `DistributedCache`.


## 8. MONITORING & OPERATIONS

- Metrics
  - Prometheus counters/histograms/gauges in `src/services/metrics_service.py`; agent stats, event throughput, AI usage, uptime.
- Logging & Alerting
  - Structured logs; dead‑letter queues in event router; alert recommendations via AI agents.
- Tracing
  - Correlation IDs in event envelopes; extendable for distributed tracing.
